# Inventory / Audit folder

Everything we use to keep the URL contract honest, in one place.

## Files

| File | Purpose |
| --- | --- |
| `urls.txt` | Authoritative list of every URL on `gomoringa.in` that must continue to respond 200 after migration. Sourced from the live sitemap on **2026-05-20**. The migration contract: every line must return HTTP 200 on the new site at the exact same path. |
| `audit-report.md` | Latest output from `scripts/audit-schema.mjs`. Regenerated by running the script — overwrites previous. The committed file shows the most recent successful run. |
| `README.md` | This file. |

## How to run the audit

```bash
# Against the live Vercel preview (current default):
BASE_URL=https://moringa-qx137s-projects.vercel.app node scripts/audit-schema.mjs

# Against local dev server:
npm run dev  # in one terminal
BASE_URL=http://localhost:3000 node scripts/audit-schema.mjs

# Post-cutover (against the real domain):
BASE_URL=https://www.gomoringa.in node scripts/audit-schema.mjs
```

## What the audit checks

For every URL in `urls.txt`:

1. **HTTP 200** — page actually exists
2. **JSON-LD validity** — every `<script type="application/ld+json">` block parses cleanly. A single trailing comma breaks Rich Results across all of Google's services.
3. **`<title>` tag** present
4. **`<meta name="description">`** present with non-empty content
5. **`rel="canonical"`** link present
6. **`og:title` + `og:image`** meta tags present
7. **GA4 tag** (`G-ZCGZ47YZ53`) present on every page
8. **Search Console verification token** present on every page

If any check fails, the script exits with code 1 — CI-friendly.

## Reading the report

`audit-report.md` includes:

- A summary table (URLs audited / passing / failing / total JSON-LD blocks / avg latency)
- A flat list of every `@type` value found across all pages (lets you confirm schema coverage at a glance)
- A per-failure section, if any URLs failed
- A "Manual run" section with per-URL deep links to:
  - **PageSpeed Insights** (run Lighthouse on each top URL)
  - **Rich Results Test** (validate each schema against Google's parser)

## Manual checks the script cannot automate

The script audits **structural** correctness. It cannot:

- Run actual Lighthouse (needs a headless browser). Use the PSI deep links in the report.
- Run Google's Rich Results Test (proprietary parser). Use the RRT deep links.
- Score Core Web Vitals (LCP / CLS / INP). Real-user metrics show up in GA4 + Search Console after launch.
- Detect content quality issues (thin content, keyword stuffing, etc.).

The plan calls for manual Lighthouse + RRT runs on the top 20 URLs before DNS cutover. The deep links in the latest `audit-report.md` are the click-list for that gate.
